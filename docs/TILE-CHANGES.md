# Changes tiles must know

Every change to the rule book, `core/v1`, the app files or a `core.*` function a tile may call, newest first. Each tile project reads this file before work (it replaces the section of the same name that used to sit in `docs/STATUS.md`, 2026-11-05). "Tiles change nothing" means no action is needed.

- 2026-11-05 - **SQL list `db/migrations.json`** (`docs/TILE-CONTRACT.md` section 4, "SQL list"; no breaking change). Every repo with SQL publishes the list of its `db/<schema>/NNN_*.sql` files in run order: `{ "repo": "<tile-id>", "files": [ { "name": "001_init", "path": "db/<schema>/001_init.sql" } ] }` (a file replaced by a later one may carry `"superseded": true`). Admin > Health compares it with `core.migrations` and shows the owner which files have not run yet, with a link to each. Check it before every push: `node ../dame-hub/dev/migrations-check.mjs .` (it also checks that every file ends with its `core.applied` line). **`hvac-notes`, `projects`, `maps`: add the file on the next delivery**; until then Admin > Health shows the tile as "No list". A tile without SQL publishes `"files": []`.
- 2026-11-05 - **`CLAUDE.md` in every repo** (template: `docs/NEW-TILE.md`, "Template: CLAUDE.md for a tile repo"). The tile's rules, ids and checks travel with its code, read by Claude, Claude Code or whoever takes the repo over. Add it on the next delivery; keep it short and pointing at the rule book rather than copying it.
- 2026-11-05 - **`core.tile_users(p_tile)`** (`db/core/009_tile_users.sql`, requested by `projects`): `(id, username, display_name)` of the active users who can open the tile - those given access plus super users - ordered by username. Same rules as `core.display_names`: call it only inside the tile's own functions (not callable by the API role); the caller must have the tile (`NO_ACCESS` otherwise); never the email, status, rights or session data. `projects`: `projects_share_get` finds it once the owner has applied 009 (filter out the caller and anyone already shared with in the tile function).
- 2026-11-05 - **`.hero-line`** in `core/v1/theme.css` (dashboard line, `docs/LINES.md`; no breaking change). Tiles change nothing.
- 2026-11-05 - **New icon `map`** (`core/v1`, no breaking change): `.icon.i-map` / `.ico.i-map`, listed in `Core.ICONS` and in the admin icon picker. Tiles change nothing.
- 2026-11-05 - **Accounts can be renamed and deleted** (`db/core/008_manage_users.sql`; no change to any function a tile calls). Tiles key by user id, never by username; a saved name is a label of its moment; no foreign key to `core.profiles` / `auth.users` that blocks a delete; new Storage folders `<user_id>/...` (`docs/TILE-CONTRACT.md` section 2). **Tile tests must change:** `core_session_start()` now refuses a session that Supabase does not have, so every `pg_temp.act_as` inserts `auth.sessions (id, user_id, created_at, updated_at)` before starting the session (two lines, see `demo/db/demo/tests.sql`). `hvac-notes` and `projects`: their `db/<schema>/tests.sql` fail with `SIGNED_OUT` until they add it; real users are not affected. `projects` shows `created_by_name` / event usernames as saved at the time; after a rename the old name shows there (acceptable as history; read current names through `core.display_names` if wanted).
- 2026-11-05 - **The installed app** (`manifest.webmanifest`, `sw.js`, `offline.html`, `core/v1` theme.css + core.js, README head block; no breaking change). Tiles add nothing: no manifest, service worker, icons or install button, ever (`docs/STANDARDS.md` section 12). On the next delivery each tile's pages take the two changed head lines from `core/v1/README.md` - `viewport-fit=cover` on the viewport meta and `<meta name="theme-color" content="#F3F7FA">` - so the page sits right under the notch inside the app; until then the only difference is a strip of page background at the top. `hvac-notes`: the old site's manifest, worker and icons are dropped, not carried over.
- 2026-11-04 - **Tiles inside the admin repo** (`core/v1/config.js` `INSIDE_CORE`, `Core.tilePath`; no breaking change). A tile the owner keeps in `dame-hub/<id>/` is served at `/dame-hub/<id>/` and the dashboard links it there. Sibling-repo tiles change nothing. The dev tooling is now `dev/serve.mjs` and `dev/test/` (was `tools/`).
- 2026-11-04 - **Tile accents** (`db/core/007_tile_accent.sql`, `core/v1` theme.css + core.js; no breaking change). Each tile has one hue from the core palette, set in Admin > Tiles > Colour; the core puts `data-accent` on `<html>` and primary buttons, tabs, chips, badges, icons, input focus and the new `.progress` / `.cover` follow it. Tiles change nothing to get it. A tile that colours sections of its own (covers, headings) replaces its colour values with `data-accent="<name>"` + `var(--accent-*)` on its next delivery; `docs/TILE-CONTRACT.md` section 2 lists the tokens and names. **`hvac-notes` keeps its current colours** (blue accent; its covers map to blue / green / orange / violet).
- 2026-11-04 - **`core.display_names(p_tile, p_ids uuid[])`** (`db/core/006_display_names.sql`, requested by `hvac-notes`): current `username` and `display_name` (plus `active`) of the authors of shared records. Call it only inside the tile's own functions; the caller must have the tile; pending accounts are never returned; max 500 ids. Listed in `docs/TILE-CONTRACT.md` section 2. Tiles that saved a name next to each record may keep it as a fallback.
- 2026-11-04 - **Embedded YouTube player allowed for `hvac-notes` only.** It adds `frame-src https://www.youtube-nocookie.com` to its CSP on pages that show videos (exact line in `core/v1/README.md`), on the conditions in `docs/SECURITY.md` section 4: click to load, iframe `src` built from a checked video id, `sandbox`, `referrerpolicy`, and a "Watch on YouTube" link. `docs/TILE-CONTRACT.md` section 6 names the exception. Other tiles: unchanged, no iframes; ask the owner through `docs/CORE-REQUESTS.md` if one needs it. `docs/TILES.md` has a new column, Exceptions.
- 2026-11-04 - **Look refresh (core/v1, no breaking change).** Day/night is now a round sun/moon icon button with a circular reveal; account menu is an avatar + name pill (also on phones, where it used to be hidden); soft brand glow behind every page (`body` is transparent, `html` carries `--bg`); primary buttons use the brand gradient; `.tabs` is a segmented control; tiles have gradient icons, a hover arrow and a staggered entrance. New tokens and classes in `core/v1/README.md` (Theme). Tiles change nothing; a tile that set its own `body` background should drop it so the glow shows. Icon classes now also work without `.icon` (`.i-<name>`).
- 2026-11-04 - Rule book: an existing site may join as a tile (`docs/NEW-TILE.md`, "Bringing an existing site in"); `docs/SECURITY.md` section 1 allows a private **source repo** for a tile's authoring copy and says shared-password encryption in a public repo is not allowed. `docs/STANDARDS.md` section 1 and the project template wording changed to match.
- 2026-11-04 - `core_me()` also returns `email` (the caller's own address). Tiles keep showing `username`; never show or store the address in a tile.
- 2026-11-04 - Site is named **DAME HUB**; theme now carries the Daikin Middle East palette (`--brand #0097E0`, night `#2FB0EC`), the layers-glyph mark and favicons in `core/v1/icons/`. Token names unchanged; `--link`, `--focus`, `--glass`, `--scrim`, `--ease`, `--brand-sky`, `--brand-navy` added. Pages add `<link rel="icon" href="/dame-hub/core/v1/icons/favicon.svg">` and the apple-touch-icon line (see `core/v1/README.md`).
- 2026-11-04 - core/v1 first version. Icons are `.icon.i-<name>`; `Core.requireLogin` returns a promise of `me`; `core.username_of` available; CSP line in `core/v1/README.md`.
