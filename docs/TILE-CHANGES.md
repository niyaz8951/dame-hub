# Changes tiles must know

Every change to the rule book, `core/v1`, the app files or a `core.*` function a tile may call, newest first. Each tile project reads this file before work (it replaces the section of the same name that used to sit in `docs/STATUS.md`, 2026-11-05). "Tiles change nothing" means no action is needed.

- 2026-11-06 - **`docs/FOUNDATIONS.md`: read it first, raise site-wide needs in the first reply** (owner: "such things are highlighted at an early stage in any chat anywhere"). The register of what every tile depends on (settled F1-F9, open F10-F23 in order). Every tile project reads it before any work; anything site-wide a chat notices, or that the tile is about to build for itself (notifications, search, history, exports, people lists ...), is said at the top of the reply and written in `docs/CORE-REQUESTS.md` before the tile builds around it. Tiles change no code; the owner adds line 0 to each tile project's instructions (the copies in `docs/tiles/` have it). - 2026-11-06 - **One access model for every tile** (`db/core/011_access.sql`, `core/v1` core.js + new share.js + theme.css + api.js, `docs/TILE-CONTRACT.md` section 5 rewritten, `docs/SECURITY.md` 3.8, `docs/STANDARDS.md` roles, `docs/NEW-TILE.md` "Who can do what"; owner: "SharePoint-like access ... one user base and one access base"). **Nothing breaks when 011 runs:** `core.require_tile`, `has_tile`, `is_tile_admin`, `core_me` keep their signatures; every user gets the level matching what he had, and 011 declares the three tiles with **aliases** so their current right names still answer the same (projects: `review` = approve, `edit` = contribute; hvac-notes: `edit` = edit, `nb_*` stay special rights; maps: `edit` = contribute, `verify` = approve). Two intended differences: a Maps user with `verify` but not `edit` can now also edit (Approve includes Contribute), and anyone with Projects can pass the unused `edit` check (no Projects function has used it since 009). What is new:
  - **Levels** `read < contribute < edit < approve < manage` in every tile; a person's level is the highest of his own and his groups'; tile admin = Manage, named only by the super user. **Groups** (Admin > Groups). In SQL: `core.require_level`, `core.tile_level`; in the page: `Core.user.level`, `Core.atLeast(level)`, `Core.requireLogin({ tile, level })`.
  - **Containers** (a project, a map, a notebook): registered by the tile (`core.container_put`), checked with `core.require_container`, listed with `core.container_ids`, described with `core.container_info`; shared from the core's **Access panel** `Core.share({ kind, id })` (everyone can edit / everyone can view / only the people and groups listed, each Can view or Can edit; the tile level is the ceiling; managers open everything, private too). Check access and Handover live in Admin.
  - **Declaration**: each tile's next SQL file runs `core.tile_declare('<tile-id>', { levels, aliases, rights, kinds, default })` for its own id (011 wrote a first one for each; the tile's own replaces it), and `docs/TILE.md` gets **Who can do what** (`docs/NEW-TILE.md` has the block).
  - **Each tile moves over in its own project chat, in this order** (each step is one SQL file + pages; tests with a container not shared and a level too low):
    - **`hvac-notes` first.** Notebooks become containers `notebook` (id = the notebook id): register each, `everyone = 'edit'` for *All users*; a notebook set to *Selected users* gets `everyone = null` and `core.shares_from_right('hvac-notes', 'nb_<id>', 'notebook', '<id>', 'edit')`; reads filter with `core.container_ids` / `core.container_level`; the notebook audience setting becomes **Share** on each notebook (managers); then declare without the `nb_*` rights and drop `hvac_notes.notebooks`. Levels: read = read; contribute = highlights, notes, replies; edit = publish pages (arrive as drafts); approve = approve / hide pages, remove anyone's notes and replies (today the manager's or `edit`); manage = *This is the whole library* and settings.
    - **`maps`.** Each map becomes a container `map` (owner = `owner_id`; private -> `everyone = null`, team can read -> `'read'`, team can edit -> `'edit'`); `maps.right_on` / `right_of` read `core.container_level`; the map's sharing setting becomes **Share** (Access panel); managers now see private maps (owner, 2026-11-06); verifying is `approve`.
    - **`projects`.** Each project becomes a container `project` (owner = `created_by`, `everyone = null`); `projects.members` move with `core.share_put(..., 'edit')`, then the table and `projects_share_*` go; `projects.can_open` reads `core.container_level`; the Share sheet becomes `Core.share`. Owners may now share their own projects (SharePoint rule; today only managers). TL Review becomes `approve` instead of the manager; the knowledge base stays `approve` tile-wide.
    - **`tools`**: nothing (one level, read).
  - **Security check** (011): pg_cron's own two policies on `cron.job` / `cron.job_run_details` are no longer reported, and only in pg_cron's own shape (hvac-notes request, 2026-11-06). Any other policy for anon/public, even in `cron`, still is.
  - **Tests**: `pg_temp.act_as` unchanged; a tile test can give levels with `core_tile_level_set` as the super user, or insert `core.tile_access (user_id, tile_id, level)`.
- 2026-11-05 - **SQL list `db/migrations.json`** (`docs/TILE-CONTRACT.md` section 4, "SQL list"; no breaking change). Every repo with SQL publishes the list of its `db/<schema>/NNN_*.sql` files in run order: `{ "repo": "<tile-id>", "files": [ { "name": "001_init", "path": "db/<schema>/001_init.sql" } ] }` (a file replaced by a later one may carry `"superseded": true`). Admin > Health compares it with `core.migrations` and shows the owner which files have not run yet, with a link to each. Check it before every push: `node ../dame-hub/dev/migrations-check.mjs .` (it also checks that every file ends with its `core.applied` line). **`hvac-notes`, `projects`, `maps`: add the file on the next delivery**; until then Admin > Health shows the tile as "No list". A tile without SQL publishes `"files": []`.

Same rules as `core.display_names`: call it only inside the tile's own functions (not callable by the API role); the caller must have the tile (`NO_ACCESS` otherwise); never the email, status, rights or session data. `projects`: `projects_share_get` finds it once the owner has applied 009 (filter out the caller and anyone already shared with in the tile function).
